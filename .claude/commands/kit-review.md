리뷰 범위: $ARGUMENTS (비어 있으면 현재 작업 트리의 변경 전체)

리뷰는 세 단계다. 기계가 확정할 수 있는 것은 스크립트가, 판단·재현이 필요한 것은 서브에이전트가 맡는다.
**Main은 리뷰하지 않는다** — 범위를 정하고, 에이전트를 띄우고, 결과를 기록·수정하는 것까지가 Main의 일이다.

이 리뷰의 축은 2026-08 외부 리뷰(codex)가 드러낸 실패 유형에서 도출됐다:
문서가 약속한 보장이 스크립트에 없거나, 읽어서는 안 보이고 돌려 봐야 보이는 우회가 있었다.

---

## 1단계 — 기계 검사

```bash
scripts/check-docs.sh        # 경로·참조(키트 + **이 저장소 자신**) · 절 이름 포인터 · 축↔에이전트 대응 · 셸 문법 · **훅 실행 권한** (`.githooks/*` 포함 — 권한이 빠지면 게이트가 조용히 fail-open 된다)
scripts/test-review-gate.sh  # 커밋 게이트(도장·훅)의 적발·통과 실측 + 뮤테이션 자기검증
scripts/test-consistency.sh  # 정합성 검사 회귀 fixture (H 마일스톤 배치 · 준비도 롤업 4분기)
scripts/test-report.sh       # report.py 회귀 fixture (Story 문서 ↔ 사이클 축약 슬롯 공존 모드)
scripts/test-docs-check.sh   # **check-docs.sh 자신의 회귀 fixture** (30 케이스) — 검사 1-c·5·6·7·8·9·10 에 위반을 심어 붉어지는지 실측
```

> 1단계는 **CI(`.github/workflows/docs-check.yml`)와 같은 검사여야 한다.** CI에 스텝이 추가되면 여기에도 추가한다 —
> 어긋나면 로컬 통과가 CI 통과를 뜻하지 않게 된다.

- **실패하면 여기서 멈추고 고친다.** 2단계로 넘어가지 않는다.
- 검사를 약화시켜 통과시키지 않는다. 오탐이면 조건을 좁히고, 끄지 않는다.

## 2단계 — 축 선택과 병렬 실행

변경된 파일로 축을 고른다. **축마다 서로 다른 에이전트를 쓴다** — 한 에이전트에 여러 축을 몰아주지 않는다.
관점을 섞으면 각 관점의 깊이가 얕아지고, 발견끼리 서로를 가리기 때문이다.

| 변경에 이것이 포함되면 | 필수 축 |
|---|---|
| (항상 — 모든 변경은 약속에 닿을 수 있다) | K1 |
| `*.md` — 문서·가이드·양식·커맨드·에이전트 정의 | K5 |
| `*.sh` — 훅·검사기·설치기 | K2 · K3 · K6 |
| `install-kit.sh` · STATUS 양식 · `MOC.md` · `adopt.md`/`stage.md` | K4 |
| 릴리스 직전 · 대규모 변경 | 6축 전부 |

| 축 | 에이전트 | 관점 |
|---|---|---|
| K1 | `kit-review-k1` | 약속–강제 대조 — "막는다"고 적힌 것이 코드 어디에 있나 |
| K2 | `kit-review-k2` | 우회 재현 — fixture를 만들어 실제로 돌려서 뚫는다 |
| K3 | `kit-review-k3` | 셸 정확성 — 인용·빈 입력·exit code·이식성 |
| K4 | `kit-review-k4` | 수명주기 경로 — 설치→첫 세션→도입→사이클이 이어지나 |
| K5 | `kit-review-k5` | 의미적 문서 정합 — 기계가 못 잡는 모순만 |
| K6 | `kit-review-k6` | 회귀 증거 — 잡는다는 주장마다 잡히는 fixture가 있나 |

선택한 축의 에이전트를 **병렬로** 띄우고, 각각에 (1) 리뷰 범위(변경 파일 목록·diff 대상)와
(2) 1단계 출력을 그대로 전달한다.

## 3단계 — 반증

2단계가 올린 **치명·높음** 발견마다 `kit-refute` 에이전트를 띄워 반박을 시도시킨다.
**반증 프롬프트에 리뷰 범위를 못 박는다 — 범위는 커밋된 것이 아니라 미커밋 작업 트리다.**
(1회전에서 반증 하나가 `git diff main HEAD`로 판정해 실재하는 변경을 "건드린 적 없다"로 잘못 기각했다)

- **반증 실패** (재현이 다시 성공했고 근거가 확인됨) → 확정
- **반증 성공** → 기각하거나 심각도 강등. 기각·강등 사유를 발견 옆에 함께 기록한다
- 보통·낮음은 반증 없이 기록한다

**치명·높음이 하나라도 확정되면 이번 회전의 판정은 실패다.**

> **이 단계에는 기계 장치가 없다** (이슈 #093). 이 하네스에는 "서브에이전트가 실제로 떴다"를
> 관측하는 자리가 없어서, Main이 반증을 건너뛰고 확정해도 훅·검사기 어디에도 안 걸린다.
> 도장(`review-stamp.sh`)은 트리만 보고 무엇이 돌았는지는 모른다 — `#020`과 **같은 신뢰 경계**다.
> 그래서 이것은 강제가 아니라 **절차**이고, 관측되는 흔적은 하나뿐이다:
> `issues.md`의 그 회전 표에서 **치명·높음 행마다 반증 결과**(확정 / 강등 사유 / 기각 사유)를 적는 것.
> 반증 결과가 안 적힌 치명·높음 행은 **반증을 안 거친 것으로 읽는다.**

## 돌아오면 Main이 한다

1. 발견 **전부**를 `issues.md`에 기록한다 — 심각도로 거르지 않는다. 기각된 것도 기각 사유와 함께 남긴다.
2. 치명·높음부터 고친다. 검사기·훅의 결함이면 **그 결함을 잡는 fixture를 먼저 만들어**(K6의 재료)
   실패를 확인한 뒤 고친다 — fixture 없이 고친 검사기 수정은 다음에 조용히 되돌아간다.
3. 수정 후 **실패했던 축만 같은 범위로 재리뷰한다.** 재리뷰 없이 "고쳤다"로 닫지 않는다.
   변경에 새 파일 유형이 들어왔으면(예: 수정 중 `.sh` 추가) 축 선택 표를 다시 적용해 축을 넓힌다.
4. **상한 3회전.** 최초 리뷰가 1회전, 수정→재리뷰가 한 회전씩이다. `issues.md` 리뷰 기록에
   **회전 수를 명시한다**(`1회전`·`2회전`…) — 지금이 몇 회전인지는 기록으로만 관측된다.
   3회전 뒤에도 치명·높음이 남으면 검사를 약화시키지 않고 `STATUS.md`에 ⛔로 올려 멈춘다.
5. 판정(통과/실패)과 남은 항목을 `STATUS.md`에 반영한다.
6. **판정이 통과면 도장을 찍는다**: `.claude/scripts/review-stamp.sh --write`(커밋될 트리를 도장에 기록).
   **그다음 커밋은 절대 규칙 2-1(승인 모드)에 따라 사용자에게 묻고 답을 받은 뒤에 한다** —
   무엇이 바뀌었는지·리뷰 결과·남은 지적을 함께 준다. 도장은 커밋 허가가 아니라 리뷰가 돌았다는 표시다.
   커밋은 `git add -A` 후 한다 — `.githooks/pre-commit`이 **커밋될 트리 == 도장 트리**일 때만 허용한다.
   도장 이후 파일을 더 바꾸면(STATUS.md 포함) 트리가 달라져 다시 막히므로, 마지막 변경까지 끝낸 뒤 도장을 찍는다.
   이 게이트가 기계로 보장하는 것은 트리 일치까지다 — "리뷰가 실제로 돌았는지"는 이 절차를 지키는 것으로만 담보된다.

## 심각도

| 등급 | 기준 |
|---|---|
| **치명** | 사용자 저장소를 훼손할 수 있다(덮어쓰기·삭제·유실), 또는 문서의 "막는다"가 거짓이다 — 우회가 재현된다 |
| **높음** | 보장이 부분적으로만 구현됐다, 수명주기 경로가 끊긴다, 잡는 증거(fixture) 없는 검사 |
| **보통** | 문서 간 모순, 오해를 부르는 서술, 문서화되지 않은 강제 |
| **낮음** | 표현·구조 개선 |

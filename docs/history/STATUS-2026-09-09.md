## 기준 구현 — 5088617

- source-map 공통 Python reader: 운영 구조 오류 차단, `<br>` 행 보존, 검사·리포트 입력 일치.
- mdm-contract.py: 명시적 adopt, Story 의존 등록, inspect 입력 고정, 12칸 ready 증거, JUnit verify.
- 파일 SHA-256과 판정 당시 입력을 대조한다. 변경 감지는 과거 판정 해시를 갱신하지 않는다.
- 준비·완료의 근거 유효성은 계산한다. source-map render는 표시만 갱신한다.
- verify는 현재 계약·코드와 실행 결과를 연결하며 실패/skip/미보고·실행 중 입력 변경을 차단한다.
- 기존 커맨드·도입·업그레이드·종료 검사와 연결. 제품의 docs/meta·docs/evidence는 보존한다.
- 운영 가이드: `templates/dev-kit/docs/guides/contract-evidence.md`.
- 상류 선언 형식에서 전체 ID를 추출해 include/defer/exclude/retire 처리 목록과 매핑을 대조한다.
- Story 영향 분류로 읽을 범위를 선택하고 행동·권한·상태·데이터·외부 영향의 비교 기록을 ready에 연결한다.
- 인계의 5칸을 현재 파일 집합·내용과 연결한다. Stop 훅과 최종 mdm-check.sh에서 날짜 대신 확인한다.
- 스냅샷·manifest·처리 목록·매핑을 검토한 묶음으로 반영한다. 강제 종료 후 차단·복원 경로를 제공한다.
- 제품 CI를 없을 때 설치한다. doctor는 파일 존재·유효한 도입·로컬 검사 실행·선택한 원격 조회를 구분한다.
- 규칙 승격을 공통 원인·실패 통제·적용 조건으로 좁히고 통합·폐기·효과 확인 절차를 추가했다.
- 변경 운영 가이드: `templates/dev-kit/docs/guides/operating-loop.md`.

## 검증

- 계약·운영 회귀 38개 통과. 계약 수정에 따른 실패, 재판정 후 통과, 과거 기록 보존,
  실행 실패 시 이전 성공 무효화, 실제 설치·업그레이드·셸 검사·리포트 연결을 확인했다.
- 표 갱신의 주석·코드 예제 오인과 escaped pipe 해시 변화는 재현 fixture를 먼저 실패시킨 뒤 수정했다.
- 기존 회귀: 문서 검사 34개, 설치·업그레이드 17개, 리포트 5개와 리뷰 게이트 통과.
- 공통 reader 최종 변경 후 정합성 회귀 179개도 통과했다. CI에 새 회귀를 더해 총 7종을 실행한다.
- 합성 파일럿 6개 시나리오 통과. 실행 중 강제 종료·복구, 누락·모순, 인계 드리프트, 설치 보존을 확인했다.
- 원격 활성화·실제 제품의 재작업 절감 효과는 측정하지 않았다. 실전 파일럿 대상이 아직 지정되지 않았다.
- 위 검증은 기준 구현 당시의 기록이다. 이후 5088617로 커밋·푸시되었다. 독립 리뷰 통과를 뜻하지 않는다.

## 한계와 후속

- 슬롯 근거의 의미, 사용자 확인의 진실성, JUnit 생산자의 신뢰성은 해시가 증명하지 않는다.
- v1은 파일 바이트·코드 파일 집합을 본다. 원격 최신성·실행 환경·항목별 의미 변화까지 추적하지 않는다.
- 새 엔진 정책 파일이 바뀌면 준비 판정도 다시 해야 한다.
- 상류 추출 설정의 완전성·영향 분류·aligned 판정·인계 문장의 충분함은 의미 리뷰가 필요하다.
- 동기화는 파일별 복구 기록으로 중단을 처리한다. 전원 손실·파일시스템 손상에 대한 트랜잭션 보장은 아니다.
- 원격 doctor는 classic branch protection만 조회하며 미조회·권한 오류는 unknown으로 남긴다.
- 로컬 workflow 페이지를 현재 방법론에 맞춰 갱신했다. 외부 아티팩트 URL은 이 작업에서 확인되지 않았다.
- 독립 리뷰 1회전 정책과 커밋 승인 정책은 유지한다.

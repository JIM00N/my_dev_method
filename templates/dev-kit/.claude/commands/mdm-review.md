리뷰 범위: $ARGUMENTS (비어 있으면 현재 작업 트리의 변경 전체)

리뷰는 **두 단계**다. 기계가 확정적으로 잡을 수 있는 것을 사람이나 에이전트에게 시키지 않는다.

---

## 1단계 — 정합성 기계 검사

```bash
.claude/scripts/check-consistency.sh
```

- **실패하면 여기서 멈춘다.** 2단계로 넘어가지 않는다. 문서가 어긋난 상태에서 코드를 보면 무엇이 기준인지 알 수 없다.
- 검사를 약화시켜 통과시키지 않는다 (절대 규칙 11). 오탐이면 스크립트의 조건을 좁히고, 끄지 않는다.

### 실패했으면 어디로 가나 ★★

**실패를 보고만 하고 끝내지 않는다.** 유형마다 해결 경로가 정해져 있다 — 그 자리에서 처리하거나,
처리할 수 없으면 무엇이 막는지 사용자에게 보고한다.

| 실패 메시지 | 무엇이 잘못됐나 | 해결 경로 |
|---|---|---|
| `준비도 점검을 안 돌렸다` | 슬롯 판정 없이 구현에 들어갔다 | **`/mdm-ready`** 실행 |
| `준비되지 않은 것이 남아 있다` | 답이 없는 칸을 둔 채 구현 중 | **`/mdm-ready`** — 질문 → 정본 반영 → `준비` 칸 갱신 |
| `완료인데 테스트가 없다` | 검증 없이 완료로 올렸다 | 테스트를 쓴다. 못 쓰면 **상태를 되돌린다** (`🔵 진행 중`) |
| `검증 조건 N개인데 테스트가 M개` | 조건 일부가 검증되지 않았다 | 모자란 만큼 테스트 추가 (`docs/guides/S6-build.md` 3절 TDD) |
| `테스트 'X'가 매핑표에는 있는데 코드에는 없다` | 이름만 적혀 있고 실물이 없다 — 개수 검사가 속는다 | 그 이름으로 테스트를 쓰거나(RED 먼저), 잘못 적은 이름이면 칸을 고친다 |
| `완료/진행 중인데 사이클이 없다` | 어느 사이클에서 했는지 추적이 끊겼다 | 매핑표 `사이클` 칸 기입 |
| `상류 변경 재검토가 남아 있다` | 상류가 바뀐 여파를 아직 안 봤다 | **`/mdm-adopt --sync`**의 6단계 — 판정 후 칸을 비운다 |
| `스냅샷이 수집 이후 변경됨` | `docs/upstream/`을 손으로 고쳤다 | **상류에서 고치고 `/mdm-adopt --sync`.** 스냅샷을 되돌린다 |
| `고아 인용: X` | 매핑표에 없는 ID를 인용했다 | 오타면 고치고, 진짜 새 요구사항이면 **`/mdm-adopt`**로 매핑표에 올린다 |
| `화면 매핑표에 있으나 interface.md에 없다` | 표면 목록과 어긋났다 | `docs/spec/interface.md`에 추가하거나 매핑표에서 뺀다 (`docs/guides/S3-interface.md`) |
| `깨진 참조` | 없는 파일을 가리킨다 | 경로를 고치거나 그 파일을 만든다 |
| `수집 기록이 없다` | `manifest.tsv`가 비었다 | **`/mdm-adopt`**로 다시 수집 |
| `표에 행이 없다` | 문서를 만들고 등재를 안 했다 — 다음 세션이 존재를 모른다 | 메시지가 가리키는 표(사이클 현황 · ADR 목록 · 활성 병렬 작업)에 행을 추가한다 |
| `행은 있는데 … 문서가 없다` · `행이 남아 있다` | 카탈로그가 없는 문서를 가리키거나, 닫힌 Story 행이 남았다 | 오타면 행을 고치고, 문서를 만들었어야 하면 만들고, 닫힌 Story면 행을 지운다 (`docs/index.md` 파일 목록 원칙) |
| `요구사항 절을 찾지 못했다` | 계층을 셀 자리가 없다 — 제목에 「요구사항」이 든 `##` 절이 하나도 없다 (setext `===`/`---` 제목이거나 최상위가 `###`) | 요구사항 절을 `##` 로 세우고 제목에 그 낱말을 넣는다 (`docs/guides/plan.md` P3 「4절 절 제목에 「요구사항」을 넣는다」) |
| `이 요구사항 절에 요구사항(###)이 없다` · `이 요구사항에 기능(####)이 없다` · `이 기능에 사양 표가 없다` | 계층이 중간에서 끊겼다 — 그 아래가 전부 구현 시점으로 미뤄진다 | **`/mdm-plan`**을 다시 돌려 끊긴 층을 채운다 (`docs/guides/plan.md` P3 4절). 세부를 Story 에서 지어내지 않는다 |
| `탭 4열이 아닌 줄이 있다` | `manifest.tsv` 형식이 어긋났다 — 그 줄은 검사 A·J 가 못 본다 | `파일<TAB>출처<TAB>수집시각<TAB>sha256` 으로 고치거나 **`/mdm-adopt`**로 다시 수집한다 |
| `수집 기록에 있는데 파일이 없다` | 스냅샷을 지웠거나 옮겼다 (도입 전에는 검사 A 가 안 돌아 J 가 직접 알린다) | **`/mdm-plan`**을 다시 돌리거나 `manifest.tsv` 의 그 줄을 지운다 |
| `사양 행을 한 건도 찾지 못했다` · `기능 소제목` | 계획이 요구사항에서 멈췄다 — 세부가 전부 구현 시점으로 미뤄진다 | **`/mdm-plan`**을 다시 돌려 기능·사양 층을 채운다 (`docs/guides/plan.md` P3 4절). 스냅샷을 손으로 고치지 않는다 |
| `영향 영역이 비었다` · `선행 칸이 비었다` · `'먼저' 칸이 비었다` | 병렬 배치를 계산할 입력이 없다 | 위와 같음 — `/mdm-plan` P3 4절의 사양 표를 채운다 |
| `권한 표를 찾지 못했다` · `'거부되면' 칸이 비었다` | 누가 무엇을 할 수 있나가 정해지지 않았다 — 구현 중에 화면마다 다르게 지어내진다 | **`/mdm-plan`** P3 2절의 권한 표를 채운다. 상류가 외부면 `docs/spec/domain.md` 4절 |

> **막히면 고치지 말고 보고한다.** 해결이 사용자 판정을 요구하면(요구사항을 뺄지, 상류를 고칠지 등)
> `docs/status/STATUS.md`의 **막힌 것**에 ⛔로 올리고 멈춘다. 추측으로 칸을 채워 통과시키지 않는다.

## 2단계 — `mdm-code-review` 서브에이전트

**서브에이전트를 띄워** 검토시킨다. 직접 하지 않는다 —
구현한 컨텍스트는 자기 우회를 보지 못하므로, 구현 관점과 리뷰 관점을 같은 작업으로 섞지 않는다.

**1단계의 출력을 그대로 서브에이전트에 전달한다.** 기계가 이미 확정한 것을 다시 판단하게 하지 않고,
판단이 필요한 것(검증 우회·드리프트·권한 경로)에만 쓴다.

---

돌아오면 Main으로서 다음을 한다.

1. **발견을 전부** `docs/quality/issues.md`에 기록한다 — **심각도로 거르지 않는다** (`docs/quality/index.md` 원칙 1·9).
   `발견` 칸은 `코드리뷰`, `유형` 칸은 index.md 유형 표에서 하나. **기록이 먼저, 수정은 그다음이다.**
   "사소해 보여서" 넘긴 것이 나중에 패턴으로 드러나고, 기록되지 않은 것은 **2회차 규칙 승격 카운터에 잡히지 않는다** —
   거른 만큼 학습 루프가 조용히 얇아진다.
   서브에이전트가 **확인 필요**로 올린 것도 기록하되 `상태: 보류`로 두고, 판정한 뒤 열거나 닫는다.
2. **치명·높음**은 수정에 손대기 전에 기록이 끝나 있어야 한다. 재현 테스트를 먼저 추가해 RED를 확인하고 고친다.
3. **리뷰는 1회전이다.** 한 번 돌리고, 발견을 고치고, **재리뷰 없이 진행한다.**
   수정은 **재현 테스트 먼저** — RED 를 확인하고 고친다. 고친 것이 맞다는 증거는
   **그 테스트와 1단계 정합성 검사**가 진다. 재리뷰가 아니다.
   수정 뒤에도 치명·높음이 남거나 **수정 자체가 새 위험을 만든다고 판단되면** 검사를 약화시키지 않고
   `docs/status/STATUS.md`에 ⛔로 올리고 멈춘다 — 한 번으로 닫히지 않는 문제는 수정이 아니라
   설계 판단이 필요하다는 신호다.

   > **왜 한 번인가** — 회전을 늘리면 검토가 깊어지는 것이 아니라 **고칠 것이 계속 새로 생긴다.**
   > 새 발견의 상당수가 **직전 회전의 수정이 만든 것**이라, 세 회전을 돌려도 마지막 수정은 검토를 못 받는다.
   > 그래서 무게를 재리뷰가 아니라 **테스트**로 옮긴다. 이 판단은 키트를 만든 저장소가 자기 리뷰에서
   > 실측했고, 거기서도 같은 규칙을 쓴다.
4. 보통·낮음도 **기록한 뒤** 이번 사이클에서 고치거나, 사유와 함께 다음 사이클·백로그로 보낸다.
5. 구현이 끝난 요구사항은 `docs/spec/source-map.md`의 상태·테스트·사이클 칸을 갱신한다.
6. 리뷰 판정(통과/실패)과 남긴 항목을 `docs/status/STATUS.md`에 반영한다.

리뷰 시점 — 이 두 시점은 건너뛰지 않는다:
- 구현 한 덩어리가 끝났을 때 (`docs/guides/S6-build.md` 3-3)
- 사이클을 닫기 전 (`/mdm-cycle-close` 2단계가 포함한다)

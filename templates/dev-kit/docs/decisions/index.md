# decisions — 의사결정 기록 (ADR)

**되돌리기 어려운 선택**의 배경과 근거. 나중에 "왜 이렇게 했지"가 반드시 나온다.
근거가 없으면 그때 판단을 못 하고, 판단을 못 하면 뒤집거나 그냥 둔다. 둘 다 나쁘다.

## 언제 ADR을 쓰나

| 쓴다 | 안 쓴다 |
|---|---|
| 데이터베이스 종류 | 변수 이름 |
| 통합 / 분리 구조 | 함수 배치 |
| 인증 방식 | 색상값 |
| 호스팅·배포 대상 | 라이브러리 마이너 버전 |
| 외부 서비스 종속 | |
| 데이터 모델의 큰 변경 | |
| 스펙과 다르게 구현하기로 한 것 | |
| AI 권장을 뒤집은 결정 | |

판단 기준: **한 달 뒤에 바꾸려면 얼마나 드나?** 크면 ADR을 쓴다.

## 규칙

- 번호는 이어서 증가. 재사용하지 않는다.
- **ADR을 만들면 위 목록 표에 행을 추가하고, 상태가 바뀌면(채택·대체됨·폐기) 그 행도 같이 고친다.**
  목록에 없는 ADR은 다음 세션이 존재를 모른다 — 파일만 만들고 끝내지 않는다.
- **채택된 ADR은 수정하지 않는다.** 생각이 바뀌면 새 ADR을 쓰고 이전 것을 `대체됨`으로 표시한다.
  기록의 가치는 "그때 무엇을 알고 그렇게 정했는가"에 있다.
- ADR을 쓰면 `docs/status/STATUS.md`의 "최근 결정"에 한 줄 남긴다.
- 양식: `ADR-000-template.md`

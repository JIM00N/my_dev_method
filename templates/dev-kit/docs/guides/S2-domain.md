# S2 — 도메인·데이터·상태 정의

**읽어야 할 때**: S1의 DoD를 전부 통과한 직후.
**입력**: `docs/spec/product.md`, `docs/guides/profiles.md`(범위 확인 — Lite는 상태 전이표까지만)
**산출물**: `docs/spec/domain.md`
**모드**: 인터뷰 · 높은 추론 설정
**다음**: S3 인터페이스 설계

> **S0로 들어왔으면 이 단계가 갭의 중심이다.** 유저플로우는 **화면 이동**(A → B)이지
> **데이터 상태 전이**(접수 → 진행중)가 아니다. **③상태 전이표는 어느 계획 도구도 담지 않으므로
> 거의 항상 갭**이고, ②데이터·④권한·⑤규칙은 담아 주는 도구도 있다 —
> S0의 계약 확인이 `❌ 갭`으로 판정한 절**만** 수행한다. 단정하지 말고 확인한다.
> ①핵심 시나리오는 유저플로우가 이미 준 경우가 많으니 대조만 하고 넘어간다.

---

## 왜 이 단계인가

기초 공사다. 여기서 빠뜨린 데이터 항목이나 상태는 나중에 발견될 때
화면·API·DB를 전부 건드려야 고쳐진다. S1의 실수는 방향이 틀리는 것이고,
**S2의 실수는 전부 뜯어고치게 되는 것**이다.

화면부터 상상하고 싶은 충동을 참는다. 화면은 데이터와 상태 위에 얹히는 것이지 그 반대가 아니다.

## 진행 방법 — 인터뷰

> **묻는 방식의 정본은 `docs/guides/index.md`의 "인터뷰 방식 — 묶어 묻기"다.**
> 한 절 안의 질문은 한꺼번에 내고 각각에 추천안을 붙인다. 앞선 답이 정해져야 뜻이 생기는 질문은 다음 차례로.
> 이 단계는 절 사이 의존이 뚜렷하다 — ①흐름이 정해져야 ②명사가 나오고, ②가 정해져야 ③상태를 물을 수 있다.
> **절 안에서는 묶고, 절 사이는 순서를 지킨다.**

### ① 핵심 시나리오 (흐름)
사용자가 이 시스템으로 처음부터 끝까지 하는 일을 **순서대로** 적는다.

- 무엇이 이 흐름을 시작시키나? (사람의 행동 / 시간 / 외부 신호)
- 그다음 무엇이 일어나나? 사람이 하나, 시스템이 하나?
- 어디서 갈라지나? (조건 분기)
- 어디서 끝나나? 성공으로 끝나는 경우와 실패로 끝나는 경우 각각.

**예외 흐름도 반드시 묻는다** — 여기서 안 물으면 구현 중에 튀어나온다:
- 중간에 취소하면?
- 필요한 정보가 없으면?
- 같은 걸 두 번 하면?
- 다른 사람이 동시에 건드리면?
- 업무 시간 밖이거나 휴일이면? (시간 기준이 있는 경우)

### ② 데이터 정의
흐름에 등장한 명사를 전부 뽑아 각각에 대해 묻는다.

- 이건 무엇인가? 한 문장 정의.
- 어떤 항목을 갖고 있나? (각 항목의 형태: 글자 / 숫자 / 날짜 / 참거짓 / 목록 / 파일)
- 필수인가 선택인가?
- 무엇으로 서로 구별하나? (같은 것인지 다른 것인지 판별하는 기준)
- 다른 데이터와 어떻게 연결되나? (1:1 / 1:N / N:M)

그리고 전체에 대해:
- **기준 장소(source of truth)는 어디인가?** 같은 정보가 두 곳에 있으면 반드시 어긋난다. 하나를 정하고 나머지는 참조로 만들거나 폐기한다.
- 기존에 쓰던 데이터가 있나? 옮겨와야 하나? 어떤 항목만?
- **삭제 정책**: 정말 지우나, 숨기나? (대부분은 숨기는 게 맞다 — 지운 이유와 함께 보관)
- **변경 이력**: 누가 언제 무엇을 바꿨는지 남겨야 하나?

### ③ 상태 정의 ★
데이터 중 **시간에 따라 단계를 오가는 것**을 찾아 상태 기계를 만든다.

- 가능한 상태를 전부 나열한다.
- 각 전이(A → B)에 대해: **무엇이 이 전이를 일으키나?** 사람의 행동인가, 시간인가, 외부 신호인가?
- 되돌아갈 수 있나? (B → A)
- 자동으로 바뀌는 상태가 있나? 조건은? (예: 일정 기간 무활동 시)
- 최종 상태는 무엇인가? 거기서 부활할 수 있나?

> **상태가 8개를 넘으면 2층으로 나눈다.**
> 큰 단계(전체 과정에서 어디까지 왔나) + 세부 상태(그 안에서 지금 무엇을 하고 있나).
> 한 층에 15개를 늘어놓으면 화면도 코드도 감당이 안 된다.

> **전이 조건 없는 상태는 상태가 아니다.** "보류중"을 만들었으면
> 무엇이 보류로 만들고 무엇이 보류를 푸는지 답할 수 있어야 한다. 못 하면 그 상태는 지운다.

### ④ 권한
- 역할별로 무엇을 볼 수 있고 무엇을 바꿀 수 있나?
- 남의 것을 볼 수 있나?
- 되돌릴 수 없는 행동(삭제·확정·발송)은 누가 할 수 있나?

> 역할이 5개를 넘으면 과설계를 의심한다. 실제로 다르게 행동해야 하는 사람 수만큼만 만든다.
>
> **이 절은 계약 확인이 `❌ 갭`으로 판정했을 때만 편다** (이 가이드 머리말의 규칙 그대로).
> `/mdm-plan` 경로면 계획 2절이 권한을 담으므로 대체로 `✅ 상류 보유`이고, 그때 `docs/spec/domain.md` 4절은
> **베끼지 않고 어디인지만 가리킨다** — 판정과 그에 따른 처리의 정본은 `docs/spec/domain.md` 4절 머리의 표다.
> 다만 **되돌릴 수 없는 행동**은 상류가 담지 않는 경우가 많다. 그것만 갭으로 따로 세워 여기서 채운다.

### ⑤ 비즈니스 규칙 ★
전이도 권한도 아닌데 **구현이 반드시 지켜야 하는 약속**을 찾는다.

- 어떤 조건이 무엇을 **제한**하는가? (예: 동의를 거부하면 *가져오기*를 막나, *전사 처리*만 막나)
- 절대 하지 않는 것이 있나? (예: 원본 파일을 수정·삭제하지 않는다)
- 계산·판정의 기준은? (예: 연락 우선순위를 무엇으로 정하나)
- 한도·상한이 있나? (한 번에 몇 개, 며칠까지)

> **규칙마다 "어기면 무슨 일이"를 함께 적는다.** 못 적으면 규칙이 아니라 취향이므로 지운다.
>
> 이 절이 비면 구현 중에 정확히 **지어내진다.** *"권한을 거부하면 파일을 아예 못 가져오나,
> 가져오되 전사만 못 하나?"* — 둘 다 말이 되고, 답이 없으면 에이전트가 하나 고른 뒤
> 다음 세션에서 다르게 고른다. 상태 전이표가 없을 때와 같은 종류의 사고다.

## 산출물 형태

`docs/spec/domain.md`에 다음이 있어야 한다:

1. 핵심 시나리오 (정상 흐름 + 예외 흐름 목록)
2. 데이터 목록 — 각각의 항목·형태·필수여부·연결관계 표
3. 상태 목록 + **전이 표** (어떤 상태에서 어떤 상태로, 무엇에 의해)
4. 권한 표 (역할 × 행동)
5. **비즈니스 규칙 표** (규칙 · 근거 · 어기면 무슨 일이 · 어디서 강제하나)
6. 기준 장소·삭제 정책·이력 보관 방침

상태 전이는 표로 적는다. 문장으로 적으면 빠진 전이가 안 보인다:

| From | To | 트리거 | 누가 | 자동/수동 | 되돌리기 |
|---|---|---|---|---|---|
| 접수 | 진행중 | 담당자 배정 | 관리자 | 수동 | 가능 |
| 진행중 | 보류 | 30일 무활동 | 시스템 | 자동 | 가능 |

(이 표는 `docs/spec/domain.md`의 전이 표와 같은 6열이다 — 그대로 붙여 넣을 수 있다)

## 자주 빠지는 함정

| 함정 | 증상 | 처방 |
|---|---|---|
| 예외 흐름 미정의 | 구현 중에 "이럴 땐 어떻게 하죠?"가 계속 나옴 | ①의 예외 질문 5개를 전부 소화한다 |
| 상태 평면 나열 | 상태 12개가 한 줄에 늘어섬 | 2층 구조로 나눈다 |
| 기준 장소 미확정 | 같은 값이 두 화면에서 다르게 보임 | 하나를 정하고 나머지는 참조로 |
| 진짜 삭제 | 지운 걸 복구해 달라는 요청이 옴 | 숨김 + 사유 보관을 기본으로 |
| 권한 과설계 | 역할 7개, 실제로는 2명이 씀 | 실제 행동이 다른 만큼만 |
| 규칙을 안 적음 | "권한 거부면 어디까지 막나"를 구현 중에 지어냄 | ⑤ — 제한·금지·기준·한도를 표로 |
| 데이터 항목 누락 | S4 API 설계에서 없는 값을 참조 | 화면이 아니라 흐름에서 명사를 뽑는다 |

## 완료 조건 (DoD)

> 표식 규칙: `(Standard+)`는 Standard·Full만, `(Full)`은 Full만 본다 — 표식 없는 항목은 모든 프로파일이 본다.
> `(사람 확인)`은 에이전트가 대신 체크하지 않는다 — 사용자에게 요청하고 받은 답을 기록한다. 근거: `docs/guides/profiles.md`.

- [ ] 핵심 시나리오가 시작·분기·종료까지 순서대로 적혀 있다 (Standard+)
- [ ] 예외 흐름(취소·정보없음·중복·동시·시간외)이 각각 답변되어 있다 (Standard+)
- [ ] 모든 데이터의 항목·형태·필수여부가 표로 있다 (Standard+)
- [ ] 데이터 간 연결관계(1:1 / 1:N / N:M)가 명시되어 있다 (Standard+)
- [ ] 기준 장소가 하나로 정해져 있다 (Standard+)
- [ ] **상태 전이 표**가 있고, 모든 전이에 트리거가 적혀 있다
- [ ] 자동 전이의 조건이 숫자로 적혀 있다
- [ ] 권한 표(역할 × 행동)가 **확보되어 있다** — 갭이면 여기 채우고, `✅ 상류 보유`면 어디인지 가리킨다 (Standard+)
- [ ] **비즈니스 규칙 표**가 있고, 각 규칙에 "어기면 무슨 일이"가 적혀 있다
- [ ] 삭제 정책과 이력 보관 방침이 정해져 있다 (Standard+)
- [ ] 산출물에 양식 플레이스홀더(`YYYY-MM-DD`·`미작성`·예시 텍스트)가 남아 있지 않다
- [ ] `docs/status/STATUS.md`의 S2가 ✅ 로 갱신되었다

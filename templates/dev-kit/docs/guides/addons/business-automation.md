# 애드온 — 업무 자동화 · AX 프로젝트

**읽어야 할 때**: 이 프로젝트가 **사람이 손으로 하던 업무를 대신하거나 보조하는 시스템**일 때.
사내 업무 자동화, 운영 대시보드, AX 컨설팅 납품 시스템이 여기 해당한다.

**해당 없으면 읽지 않는다.** 일반 소프트웨어(앱·도구·라이브러리·서비스)에는 적용되지 않는다.

이 문서는 S1~S4를 **대체하지 않고 추가**한다. 각 절이 어느 단계에 끼워지는지 표시했다.

---

## 판별 — 이 애드온이 필요한가

아래에 둘 이상 해당하면 필요하다.

- 지금 사람이 손으로 하고 있는 일이 있고, 그걸 줄이려는 것이다
- 도입 근거로 시간·비용 절감을 제시해야 한다
- 사용자가 "고객"이 아니라 "직원"이다
- 성공 여부를 업무 지표로 측정한다

---

## 1. 병목 파악 ★ (→ S1에 추가)

**자동화의 가치는 병목을 얼마나 정확히 짚었는가에서 나온다.**
기능을 많이 만드는 것이 아니라, 아픈 지점 하나를 정확히 없애는 것이 성과를 만든다.

### 인터뷰로 찾는다

사용자가 자기 병목을 스스로 알고 있는 경우는 드물다. 질문이 찾아낸다.

- 이 업무의 처음부터 끝까지를 순서대로 말해 달라
- 각 단계에서 **얼마나 걸리나?** 하루 몇 건인가?
- 어디서 **기다림**이 생기나? 누구를 기다리나?
- 어디서 **되돌아가나?** (다시 물어보고, 다시 받고, 다시 하는 지점)
- 어디서 **놓치나?** 놓치면 어떻게 알게 되나? 알게 되긴 하나?
- 같은 정보를 **두 번 이상 입력**하는 곳은 어디인가?
- 이 중에 **가장 짜증나는 것** 하나를 고른다면?

### 병목의 전형적 형태

| 형태 | 신호 | 자동화 여지 |
|---|---|---|
| 전달 누락 | "그거 누가 하기로 했었죠?" | 담당자·기한 자동 생성 |
| 상태만 있고 행동이 없음 | 기록은 하는데 다음 행동이 안 생김 | 상태 전이 시 할 일 자동 생성 |
| 흩어진 기준 장소 | 엑셀·메신저·시스템에 같은 정보 | 하나로 모으기 |
| 반복 입력 | 같은 값을 여러 곳에 | 한 번 입력, 나머지 참조 |
| 알아채지 못함 | 지나고 나서야 발견 | 기한 감시 + 알림 |
| 수동 집계 | 매주 엑셀로 취합 | 자동 집계 화면 |

### 대상 선정

병목을 여러 개 찾았으면 **하나만 고른다.**

우선순위 기준:
1. **시간 민감도** — 늦으면 가치가 사라지는 것부터 (기회는 시간이 지나면 식는다)
2. **빈도 × 아픔** — 자주 일어나고 아픈 것
3. **경계 명확성** — 어디까지가 이 문제인지 선을 그을 수 있는 것

산출물: `docs/spec/product.md`에 **병목 절**을 추가한다.

## 2. 수동 / 자동 경계 ★ (→ S1에 추가)

**전부 자동화하려 하면 실패한다.** 판단이 필요한 일은 사람이 해야 한다.
자동화의 역할은 판단을 대신하는 게 아니라 **판단할 것을 제때 사람 앞에 놓는 것**이다.

세 칸으로 나눈다:

| 구분 | 기준 | 예 |
|---|---|---|
| **자동** | 규칙으로 100% 결정되는 것 | 감지, 생성, 배정, 기한 계산, 집계 |
| **자동화 보조** | 시스템이 준비하고 사람이 확정 | 알림, 초안 작성, 후보 제시 |
| **수동** | 판단·관계·예외가 개입 | 대화, 협상, 최종 결정, 예외 처리 |

각 항목을 세 칸 중 하나에 넣는다. 애매하면 **보조**로 넣는다 — 자동으로 넣었다가 사고 나는 것보다 낫다.

## 3. KPI 와 ROI (→ S1에 추가)

### KPI
- 지표 하나를 고른다. **현재값과 목표값을 숫자로.**
- 어떻게 측정하나? 시스템이 자동으로 셀 수 있나?
- 무엇을 "완료"로 칠 것인가? (경계를 명확히 — 예: 통화 실패해도 문자를 남기면 완료)

### ROI (도입 근거를 제시해야 하는 경우)
```
절감 = (건당 소요 시간 × 건수 × 인건비 단가) − 시스템 운영비
방지 = (놓친 비율 × 건수 × 건당 기대 가치)
```
- 근거가 되는 숫자는 **사용자에게서 받은 것**이어야 한다. 추정치면 추정임을 표시한다.
- 과장하지 않는다. 도입 후 측정되면 드러난다.

## 4. 업무 흐름 정의 (→ S2에 추가)

일반 S2의 "핵심 시나리오"에 업무 특유의 항목을 더한다.

- **영업일·업무시간 기준**이 있나? 업무시간 밖에 들어온 건은 언제부터 세나?
- **공휴일**을 어떻게 처리하나? (공공 데이터 연동 필요 여부)
- **담당자 부재**(휴가·퇴사) 시 그 사람의 건은 어떻게 되나?
  - 복귀 후에 돌려주나, 대체 담당자가 계속 맡나?
  - 고객 입장에서는 담당자가 바뀌는 게 나은가 그대로가 나은가?
- **위임**이 있나? 누가 누구에게 넘길 수 있나? 넘어간 건의 기한은?
- **잘못 들어온 건**은 어떻게 하나? (삭제하지 말고 사유와 함께 제외 보관)

## 5. 기존 데이터 승계 (→ S2에 추가)

거의 항상 엑셀이나 다른 시스템이 이미 있다.

- 어떤 항목을 가져오나? **전부 가져오지 않는다** — 실제로 쓰는 것만.
- 기존 시스템은 폐기하나 병행하나? **병행은 기준 장소를 둘로 만든다** — 폐기 시점을 정한다.
- 옮기는 동안의 이중 입력은 어떻게 처리하나?

---

## 6. 알림·배치 설계 (→ S4에 추가)

업무 자동화의 실질적 산출물은 대부분 **알림**이다. 알림이 부실하면 시스템을 안 본다.

각 알림마다:
- **언제** 보내나? (시각을 정한다 — 업무 중 확인 가능한 시간대)
- **누구에게** 가나? 담당자? 관리자? 둘 다?
- **무엇이 담기나?** 바로 행동할 수 있는 정보인가?
- **클릭하면 어디로** 가나? (해당 건이 여러 개일 수 있으면 목록으로)
- **처리될 때까지 반복**하나, 한 번만 보내나?
- **끄는 방법**이 있나?

| 알림 | 시각 | 대상 | 반복 | 클릭 시 이동 |
|---|---|---|---|---|
| | | | | |

> **알림 채널 자체가 고장 날 수 있다.** 메일이 안 나가면 아무도 모른다.
> 보조 채널(메신저 웹훅 등)을 등록할 수 있게 만든다.

## 7. 운영 지표 화면 (→ S3에 추가, 해당하면)

성과를 보여줘야 하는 경우, 숫자를 층으로 나눈다. 한 덩어리로 보여주면 오해가 생긴다.

| 층 | 의미 |
|---|---|
| 전체 규모 | 진행 중인 것 전부의 합 |
| 가중 예상 | 단계별 성공 확률 × 규모 — **확률은 보수적으로** |
| 확정 | 실제로 확정된 것만 |

## 애드온 완료 조건

일반 DoD에 더해:

- [ ] 병목이 인터뷰로 도출되었고, 그중 **하나**를 대상으로 골랐다
- [ ] 모든 업무 항목이 자동 / 보조 / 수동 세 칸에 배치되어 있다
- [ ] KPI에 현재값·목표값·측정 방법이 있다
- [ ] (필요 시) ROI 계산 근거 숫자의 출처가 표시되어 있다
- [ ] 영업일·업무시간·공휴일·부재·위임 처리가 정의되어 있다
- [ ] 기존 데이터 승계 범위와 기존 시스템 폐기 시점이 정해져 있다
- [ ] 알림 표가 채워져 있고, 보조 채널이 있다

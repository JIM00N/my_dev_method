# 학습·실행 모드 — 기술 의사결정

**읽어야 할 때**: 기술·도구·구조·권한 선택을 새로 해야 하거나, 기존 기본값을 적용할지 판단할 때.
**목적**: 질문을 줄이는 것이 아니라, 장기적으로 재사용할 판단을 학습으로 축적하고 반복 질문은 실행으로 전환한다.

---

## 핵심 원칙

**한 기술씩**이 아니라 **한 결정 묶음씩** 진행한다.

예: “인증·권한 접근 모델”은 하나의 결정 묶음이다. 프레임워크·DB·배포를 한 번에 던지지 않는다.

질문은 다음 중 하나를 바꿀 때만 한다.

- 제품 범위·서비스 페르소나·권한
- 보안·비용·되돌리기 비용
- 다음 구현의 인터페이스나 데이터 모델
- 장기적으로 반복될 기본 선택

답이 어떤 선택도 바꾸지 않으면 질문하지 않는다. 권장안과 이유를 기록하고 진행한다.

## A. 학습 모드

다음 중 하나면 학습 모드를 쓴다.

- 사용자에게 새로운 영역이다.
- 되돌리기 어렵거나 비용·보안·권한 영향이 크다.
- 여러 스토리·프로젝트에서 반복될 기본 선택이 된다.
- 사용자 또는 이후 검토자가 결과를 이해해야 한다.

순서:

1. 결정의 목적과 제약을 한 문장으로 확인한다.
2. 선택지마다 `무엇인가 / 장점 / 단점·주의점 / 대체제 / 추천 이유`를 설명한다.
3. 사용자에게 **한 결정 묶음씩** 선택을 받는다. 답하기 어렵다면 권장안을 채택할 수 있다.
4. 선택·대체제·이유·재검토 조건을 `docs/spec/stack.md` 또는 ADR에 기록한다.
5. 재사용 가능한 기본값이면 아래 형식으로 남긴다.

```yaml
default_decision: 역할 기반 권한 + 리소스 소유권 검사
applies_when: 서비스 페르소나가 서로 다른 데이터 범위를 가질 때
why: 최소 권한과 데이터 격리를 함께 보장
revisit_when:
  - 조직·테넌트 단위가 추가될 때
  - 외부 파트너가 접근할 때
  - 민감 데이터 접근 정책이 바뀔 때
```

## B. 실행 모드

이미 학습·기록된 기본값이 있고 이번 프로젝트에 예외가 없으면 실행 모드를 쓴다.

1. 관련 기본 결정과 ADR을 읽는다.
2. 기본값을 적용한다.
3. 다음만 짧게 보고한다: 적용한 기본값, 이번 프로젝트의 예외, 새 위험.
4. 예외·새 제약·재검토 조건이 생길 때만 학습 모드로 되돌아간다.

같은 기초 설명이나 이미 끝난 선택지를 매번 다시 질문하지 않는다.

## 기록과 완료

- 기술 선택: `docs/spec/stack.md`
- 되돌리기 어려운 선택: `docs/decisions/ADR-*.md`
- 현재 세션의 열린 선택: `docs/status/STATUS.md`
- 이 가이드의 적용은 S1~S4에서 특히 중요하다.

**완료 조건**: 각 기술·권한·구조 선택이 학습 또는 실행 중 어느 모드였는지, 선택 이유와 재검토 조건이 추적 가능하다.

# guides — 단계별 실행 지시서

각 단계를 **어떻게** 수행하는지의 절차서. 프로젝트가 달라져도 거의 그대로 쓴다.

**한 번에 하나만 읽는다.** 지금 단계가 아닌 가이드는 읽지 않는다 — 컨텍스트 낭비이고, 앞선 단계의 결정을 뒤집게 만든다.

## 단계 목록

| 단계 | 파일 | 무엇을 정하나 | 스킵 조건 |
|---|---|---|---|
| S1 | `S1-problem.md` | 누가 쓰고, 무슨 문제를 풀고, 어디까지 만드나 | 없음 |
| S2 | `S2-domain.md` | 어떤 데이터가 있고 어떤 상태를 오가나 | 저장할 데이터가 없으면 축약 |
| S3 | `S3-interface.md` | 사용자·외부와 만나는 표면(화면/API/CLI) | 없음 |
| S4 | `S4-architecture.md` | 무엇으로 어떻게 짓고, 어떻게 안 무너지게 하나 | 없음 |
| S5 | `S5-ui.md` | 어떻게 보이나 | **화면이 없으면 스킵** |
| S6 | `S6-build.md` | 짓고, 검수하고, 배포한다 | 없음 |

## 전 단계 공통 (단계가 아니라 판단 기준)

| 파일 | 언제 읽나 | 무엇을 정하나 |
|---|---|---|
| `profiles.md` | S1에서 사분면을 확정한 직후, 절차가 무겁게 느껴질 때 | 절차량 — Lite / Standard / Full |
| `decision-modes.md` | 기술·권한·구조를 새로 선택하거나 기본값을 적용할 때 | 학습 모드와 실행 모드 전환, 재사용 가능한 기본 결정 |
| `error-learning-ingest.md` | 새 에러 기록이 생겼을 때 (`/ingest-errors`) | 별도 에이전트의 종합·인제스트 절차 |

## 모드 전환 ★

- **S1~S4 = 설계 단계 → 인터뷰 모드.**
  AI가 사용자를 인터뷰해서 정의를 완성한다. 사용자가 답을 미리 알고 있을 필요가 없다 — 질문이 답을 끌어낸다.
  **추론을 가장 높게 쓴다** — Claude Code는 `ultrathink`(또는 `/model`에서 상위 모델), Codex는 reasoning effort `high` 이상.
  여기 품질이 전체 결과를 결정하므로 토큰을 아끼지 않는다.

- **S5~S6 = 구현 단계 → 검수 루프 모드.**
  "구현 → 검수 요청 → 사람이 직접 확인 → 피드백 → 수정"의 반복. 인터뷰는 끝났다.
  추론은 보통으로 내리되, **원인 불명 버그·설계 변경 판단에서는 다시 올린다.**

## 인터뷰 모드 기본 프롬프트

새 기술·권한·구조 선택이 있으면 먼저 `decision-modes.md`를 읽는다. **모든 질문을 없애지 않는다.** 새로운·되돌리기 어려운·반복될 선택은 학습 모드로, 이미 기록된 기본값은 실행 모드로 처리한다.

`/stage [n]`이 이 진입 절차를 대신 수행한다.

```
docs/guides/S<n>-*.md 를 읽고, 그 단계를 완성하기 위해 나를 인터뷰해 줘.
- 답이 실제 선택을 바꾸는 질문만 해 줘.
- 한 번에 한 기술이 아니라 한 결정 묶음만 다뤄 줘.
- 내가 답하기 어려운 건 네 추천안과 그 근거를 먼저 제시해 줘.
- 내가 놓치고 있는 게 보이면 지적해 줘.
- 인터뷰가 끝나면 docs/spec/<산출물>.md 에 정리하고 DoD 체크리스트를 대조해 줘.
```

## 검수 루프 모드 기본 프롬프트

```
구현된 부분을 내가 직접 확인하겠다.
docs/quality/test-scenarios.md 기준으로 내가 눌러볼 순서를 알려 줘.
확인해야 할 것과 정상이라면 어떻게 보여야 하는지를 각 항목에 적어 줘.
```

## 애드온

**프로젝트 성격**에 따라 추가로 읽는 문서. 해당 없으면 읽지 않는다.

| 애드온 | 언제 | 무엇이 추가되나 |
|---|---|---|
| `addons/business-automation.md` | 사내 업무 자동화·AX 컨설팅 프로젝트 | 병목 파악, 수동/자동 경계, ROI·KPI 산출, 배치·알림 설계 |

## 공통 원칙

1. **단계를 외우지 말고 구조만 안다.** 실제 수행은 AI와의 대화로 한다.
2. **각 단계는 산출물 파일 하나로 끝난다.** 산출물이 없으면 그 단계는 끝난 게 아니다.
3. **DoD 전부 통과해야 다음 단계로 간다.** 하나라도 비면 그 자리에서 채운다.
4. **이 6단계는 기능을 추가할 때마다 다시 밟는다.** 최초 구축 전용이 아니다. 두 번째부터는 범위가 작아 훨씬 빠르다.
5. **절차량은 프로파일이 정한다.** 무겁게 느껴지면 프로파일을 확인한다 — 다만 테스트·기록·학습 루프는 어느 프로파일에서도 줄이지 않는다.

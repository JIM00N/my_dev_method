# 프로파일 — 절차량을 프로젝트 크기에 맞춘다

**읽어야 할 때**: S1에서 난이도 사분면을 확정한 직후. 이후 각 단계 진입 시 범위 확인용. 그리고 절차가 무겁게 느껴질 때.
**입력**: `docs/spec/product.md`의 난이도 사분면
**산출물**: `docs/spec/product.md`의 프로파일 칸 + `docs/status/STATUS.md` 머리말
**모드**: 판정 (인터뷰 아님 — 사분면이 답을 정한다)

---

## 왜 필요한가

의례가 작업량을 넘어서면 사람은 방법론을 **일부만 지키는 게 아니라 통째로 버린다.**
개인 도구 하나에 20개 문서와 6단계 DoD와 스테이징 환경을 요구하면 두 번째 프로젝트에서 이 키트는 안 쓰인다.

S1의 난이도 사분면은 이미 프로젝트의 실제 크기를 알고 있다. **그 답이 절차량을 정하게 한다.**
사분면을 계산만 하고 쓰지 않으면 계산할 이유가 없다.

## 판정

`docs/spec/product.md`의 사분면 그대로 읽는다.
"원격"은 내 컴퓨터 밖 전부다 — **사내망도 원격이다.** 인터넷 공개만 원격인 게 아니다.

| 사분면 | 프로파일 | 한 줄 |
|---|---|---|
| 나만 쓴다 × 내 컴퓨터에서만 | **Lite** | 실수해도 나만 다친다. 기록은 최소, 학습 루프는 유지 |
| 나만 쓴다 × 원격에서도 | **Standard** | 내 컴퓨터를 벗어나는 순간 보안이 시작된다 |
| 남도 쓴다 × 내 컴퓨터에서만 | **Standard** | 남이 쓰는 순간 예외 처리가 본체가 된다 |
| 남도 쓴다 × 원격에서도 | **Full** | 전부 한다. 줄이지 않는다 |

민감정보(개인정보·대외비)를 다루면 **사분면과 무관하게 Full**이다.
돈이 오가거나 되돌릴 수 없는 외부 행동(발송·결제·삭제)이 있으면 **최소 Standard**다.

## 절차량은 어디서 강제되나 ★

이 문서는 범위의 **근거**이고, 실제 게이트는 **각 가이드 DoD의 프로파일 표식**이다.
절대 규칙 2가 DoD를 유일한 통과 기준으로 정했으므로, 축약도 DoD 항목의 표식으로만 존재한다.

- 표식 없는 항목 — 모든 프로파일이 본다.
- `(Standard+)` — Standard·Full만 본다. Lite는 건너뛴다.
- `(Full)` — Full만 본다.
- `(사람 확인)` — 프로파일과 무관하게, 에이전트가 대신 체크하지 못한다. 사용자의 확인 답변을 받아 기록한다.

이 표와 DoD 표식이 어긋나면 **DoD 표식이 틀린 것이다** — 이 표에 맞게 고친다.

## 프로파일별 범위

| 항목 | Lite | Standard | Full |
|---|---|---|---|
| S1 문제·범위 | 축약 (사분면·프로파일 · **커밋 정책** · 비목표 · 성공 기준 · 한 문장 정의) | 전체 | 전체 |
| S2 도메인·상태 | 상태 전이표만 | 전체 | 전체 |
| S3 인터페이스 | 표면 목록만 | 전체 | 전체 |
| S4 구조·스택 | `stack.md` + `code-conventions.md` 1절 | 전체 | 전체 |
| S4 안정성 7종 | 1·4·5번만 | 전체 | 전체 + 백업 복구 실연 |
| S5 시각 설계 | 스킵 가능 | 화면 있으면 수행 | 화면 있으면 수행 |
| S6 사이클·검수·기록·리뷰 | **전부 수행** | 전부 수행 | 전부 수행 |
| 환경 | 로컬만 | 로컬 + 프로덕션 | 로컬 + 스테이징 + 프로덕션 |
| ADR | 되돌리기 어려운 것만 | 되돌리기 어려운 것만 | 되돌리기 어려운 것만 |
| Story 문서 | 생략 (사이클 문서에 흡수) | 권한 영향이 있거나 병렬로 돌릴 것만 | 전부 |
| 검수 시나리오 작성 | 해당 유형 전부 작성 | 해당 유형 전부 작성 | 해당 유형 전부 작성 |
| 수동 검수 실행 횟수 | 핵심 경로 1회 | 5~10회 | 15~20회 |
| 자동 테스트 | 필수 | 필수 | 필수 |
| 코드리뷰 (`/review`) | 필수 | 필수 | 필수 |

**「병렬로 돌릴 것」은 사이클을 열 때 사람이 정한다** — Story 문서의 영향 범위(2절)를 보고 정하는 것이 아니다.
그러면 순환이다: 문서를 만들지 말지가 지금 판정 중인 것인데 판정에 그 문서가 필요해진다.
기준은 하나다 — **이 항목을 다른 항목과 동시에 다른 에이전트에게 줄 생각인가.** 그렇다면 문서를 만든다
(동시에 도는 에이전트끼리는 서로의 영향 범위를 문서로만 안다). **기계 장치는 없다 — 권고다.**

**`Story 문서` 행이 "누가 Story 문서를 갖나"의 정본이다.** 프로파일과 속성(권한 영향·병렬)을 함께
정하는 곳은 이 행 하나이고, 다른 문서는 이 행을 **가리키기만** 한다 — 한쪽만 프로파일로, 다른 쪽만
속성으로 말하면 `Standard`+`병렬`이나 `Full`+`권한무영향` 같은 조합에서 서로 반대 답이 나온다.
문서를 만드느냐와 **크기 판정을 하느냐는 별개다** — 만들지 않는 항목도 전부 판정 대상이다
(`docs/guides/ready.md` 「Story 크기 — 어디서 멈추나」).

문서 부담을 미리 알고 고른다: 설계 문서는 Lite에서 축약되지만, 운영 문서(STATUS·issues·
test-scenarios·rules-learned·learning-log·roadmap·사이클 문서)는 프로파일과 무관하게 쓰인다.
**Lite도 손대는 문서는 15개 안팎이다** — 대신 각 문서의 깊이가 얕다. "6개"가 아니다.

### Lite에서도 절대 줄이지 않는 것 ★

크기와 무관하게 이것들은 **없으면 방법론이 아니다.**

1. **비목표** — "이번에 만들지 않을 것"은 Lite에서도 비어 있으면 안 된다.
2. **상태 전이표** — 나중에 넣기 가장 어려운 것. 개인 도구도 상태는 꼬인다.
3. **`stack.md`** — 여기 없는 것을 임의로 도입하지 않는다. 훅이 강제한다.
4. **자동 테스트** — 사람이 안 쓰던 이유는 작성 비용이었고, 그 이유는 사라졌다.
5. **`issues.md` 기록 → 2회차 규칙 승격** — 학습 루프. 이걸 빼면 다음 프로젝트가 처음부터 시작한다.
6. **`STATUS.md` 갱신** — 세션 연속성. 훅이 강제한다.
7. **검증 우회 금지** (절대 규칙 11) — `/review` 코드리뷰가 잡는다.

Lite는 **설계 문서를 줄이는 것**이지 검증과 학습을 줄이는 것이 아니다.

## 승급

프로파일은 고정이 아니다. 아래가 생기면 **그 자리에서 승급하고** `docs/status/STATUS.md`에 기록한다.

| 신호 | 어디로 |
|---|---|
| 나 말고 다른 사람이 쓰기 시작했다 | → Standard |
| 내 컴퓨터 밖(사내망·인터넷)에 열었다 | → Standard |
| 실데이터·개인정보가 들어왔다 | → Full |
| 돈·발송·삭제 등 되돌릴 수 없는 행동이 생겼다 | → 최소 Standard |
| 2회차 승격 규칙이 있는데도 같은 유형 이슈가 3회 이상 반복된다 | → 한 단계 위. 이미 Full이면 승급할 곳이 없다 — 절차가 아니라 설계 문제다. 해당 영역의 ADR·구조를 재검토한다 |

(같은 유형 **2회째의 규칙 승격**은 프로파일과 무관한 별개 장치다 — `docs/quality/index.md`.)

**강등은 하지 않는다.** 한 번 올라간 프로파일은 그 프로젝트 안에서 내려오지 않는다.

## 기록

- `docs/spec/product.md`의 프로파일 칸에 판정과 근거를 적는다.
- `docs/status/STATUS.md` 머리말에 `**프로파일**: Lite | Standard | Full`을 둔다.
- 승급하면 날짜와 계기를 **두 곳에** 남긴다: `docs/spec/product.md`의 **승급 이력 표**(영구 기록)와
  `docs/status/STATUS.md`의 최근 결정 한 줄. 최근 결정은 5개까지만 남으므로 밀려 나가고,
  **왜 이 프로파일인지의 근거는 표에 남는다.**

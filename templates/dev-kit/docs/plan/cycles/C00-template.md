## 이번에 만들 것

> **`/mdm-ready`를 먼저 돌린다.** 준비 칸에 `❌`가 남은 것은 여기 올리지 않는다 —
> 답이 없는 칸은 구현 중에 에이전트가 지어낸다 (`docs/guides/ready.md`).
>
> **여기 올라오는 한 항목이 곧 Story 하나다** (Story 문서를 만들든 안 만들든).
> 한 문장에 **트리거 하나·종료 상태 하나**로 써지는 것만 올린다 —
> 크기 기준의 정본은 `docs/guides/ready.md` 「Story 크기 — 어디서 멈추나」다.
> 프로파일이 Lite여도 **문서를 안 만드는 것이지 크기 판정을 건너뛰는 것이 아니다.**
>
> **각 항목에 요구사항 ID를 인용한다.** 인용 없는 항목은 어느 요구사항 근거로 만드는지 알 수 없고,
> `docs/spec/source-map.md`에 없는 ID를 인용하면 정합성 검사가 고아 인용으로 잡는다.

| 요구사항 | 무엇을 | 준비 | 완료 |
|---|---|---|---|
| <요구사항 ID> | | <✅ ST-001> | ⬜ |
| <요구사항 ID> | | <❌ 규칙·전이> | ⬜ |

`준비` 칸은 `/mdm-ready` 판정의 요약이다. **Story 문서를 만든 항목**이면 **그 Story ID를 적고**(`✅ ST-001`),
**만들지 않은 항목**이면 아래 축약 슬롯의 결과를 적는다. (프로파일이 아니라 **문서 유무**로 갈린다)

> **한 요구사항에 Story가 여럿이면 행을 여럿 쓴다** — 같은 요구사항 ID가 여러 행에 반복되는 것이 정상이다.
> (요구사항 하나를 한 행으로 접고 Story 셋을 한 칸에 섞는 것이 `docs/guides/ready.md` 함정 표의 마지막 행이다.
> 요구사항 단위로 한 행씩 접는 표는 `docs/spec/source-map.md` 매핑표 쪽이고, 그 `준비` 칸이 Story 롤업이다)

### 개발 준비 슬롯 (Story 문서를 만들지 않는 항목) ★

**Story 문서를 만든 항목은 이 표에서 지운다** — 그 슬롯의 자리는 `docs/plan/stories/ST-<nnn>.md` 1-1절이다.
**Story 문서를 만들지 않는 항목만 여기 남는다.** 어느 항목이 문서를 갖는지는 프로파일이 정한다
(`docs/guides/profiles.md`의 `Story 문서` 행이 정본 — 여기서 다시 세지 않는다).
**남는 항목이 하나도 없으면 이 절을 지운다.**

> **"프로파일이 Lite가 아니니 이 절을 통째로 지운다"가 아니다.** 문서 없는 항목이 하나라도 있으면
> 그 항목은 트리거·결과를 적을 칸을 잃고, 「시작 전 확인」의 크기 판정 체크박스를 근거 없이 체크하게 된다.

판정: `✅` 답 있음 · `❌` 답 없고 갈림 · `—` 해당 없음(**이유 필수**)

| 항목 | 요구사항 | 상태 전이 | 권한 | 규칙 | 데이터 | 예외 | 표시 | 검사 명령 | 선행·트리거·동작·결과 | 검증 조건 |
|---|---|---|---|---|---|---|---|---|---|---|
| <위 목록의 항목> | <요구사항 ID> | | | | | | | | | |

- **한 행 = 한 항목(=Story) 하나다.** 위 「이번에 만들 것」의 **행 중 Story 문서를 만들지 않은 것**이
  여기 그대로 온다 — 요구사항 하나에 그런 항목이 셋이면 여기도 세 행이고, `요구사항` 칸에 같은 ID가 세 번 나온다.
- 앞 7칸은 **정본을 가리킨다** — `domain #3` 처럼 어느 행인지만. 내용을 여기 베껴 쓰지 않는다.
- `선행·트리거·동작·결과`는 이 항목에서만 의미 있는 것이라 여기 직접 쓴다 (한 칸에 묶어 짧게).
- 자세한 뜻과 절차는 `docs/guides/ready.md`.

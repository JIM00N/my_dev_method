# plan — 계획

**어떤 순서로 만드는가.**

## 파일

| 파일 | 내용 | 언제 |
|---|---|---|
| `roadmap.md` | 마일스톤 + **백로그** | 범위 밖 아이디어가 나올 때마다 |
| `cycles/C<nn>-<이름>.md` | 사이클별 실행 계획 | 사이클 시작 시 생성 |
| `archive/index.md` | 완료된 사이클·Epic 기록의 카탈로그 | 종료된 계획을 현재 계획에서 뺄 때 |
| `archive/MOC.md` | 완료된 계획의 탐색 허브 | 과거 계획의 맥락을 찾아야 할 때 |

## 핵심 원칙

1. **사이클에 없는 것은 만들지 않는다.** 좋은 아이디어가 떠오르면 구현하지 말고 `roadmap.md` 백로그로.
2. **한 사이클 = 「구축 → 검수 → 안정화 → 배포」 한 바퀴.**
3. 첫 사이클은 **가장 좁은 동작 경로 하나**. 처음부터 끝까지 이어지되 얇게.
4. 사이클이 크다는 신호 — 완료 조건 10개 초과 / 화면 5개 초과 / "이것도 있어야"가 3회 이상. 하나라도 걸리면 자른다.
5. 완료된 사이클·Epic의 상세는 archive로 옮긴다. `roadmap.md`와 STATUS에는 현재·다음 작업만 남긴다.

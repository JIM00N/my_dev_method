## 2. 영향 범위 ★

이 Story가 **실제로 손대는 곳**을 미리 적는다. 병렬 작업 시 파일 소유권 충돌을 여기서 막는다.

| 구분 | 대상 |
|---|---|
| 손대는 파일·모듈 | |
| 바뀌는 데이터·스키마 | |
| 바뀌는 인터페이스(화면·API·CLI) | |

> 다른 Story와 **같은 파일**을 손대야 하면 병렬로 돌리지 않는다.
> 데이터·권한·API·코드 컨벤션·파일 소유권이 확정된 뒤에만 병렬 구현한다.

## 3. 권한 계약 ★★

**서비스 페르소나의 권한**과 **개발 에이전트의 작업 권한**은 다른 것이다. 섞지 않는다.

### 3-2. 개발 에이전트 (이 Story를 구현하는 에이전트가 무엇을 해도 되나)

| 항목 | 이 Story에서 |
|---|---|
| **허용 행동** | 예: `src/orders/**` 수정, 테스트 추가, 마이그레이션 초안 작성 |
| **거부 행동** | 예: 스키마 파괴적 변경, 프로덕션 접근, 실데이터 조회, 다른 Story 파일 수정, 새 패키지 도입 |
| **사용자 승인이 필요한 것** | |
| **막히면** | `STATUS.md`에 ⛔로 올리고 멈춘다. 추측으로 진행하지 않는다 |

> 개발 에이전트는 **프로덕션 데이터와 비밀값에 접근하지 않는다.**
> 스택에 없는 패키지 도입은 훅이 막는다 (`.claude/hooks/guard-dependency.sh`).

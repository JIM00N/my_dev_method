# quality — 문제 기록·검수·재발 방지

이 폴더가 **"만들었는데 되는지는 모르는 상태"**를 막는다.

## 파일

| 파일 | 무엇 | 언제 쓰나 |
|---|---|---|
| `test-scenarios.md` | 사람이 직접 눌러볼 검수 목록 | 사이클 구현이 끝났을 때 만든다 |
| `issues.md` | 발견된 모든 문제의 기록 | 문제를 발견한 **즉시** |
| `rules-learned.md` | 재발 방지 규칙 | 같은 유형 문제가 **2번째**일 때 |

## 흐름 ★

```
검수 시나리오 작성
      ↓
사람이 직접 실행 (15~20회)
      ↓
문제 발견 → issues.md 에 기록  ← 기록이 먼저, 수정은 그다음
      ↓
새 기록 → 별도 Error Learning Agent가 종합·인제스트
      ↓
원인 분석 → 수정
      ↓
같은 시나리오로 재검수  ← 이걸 안 하면 닫지 않는다
      ↓
통과하면 이슈를 유형별 archive로 이동
      ↓
같은 유형이 2번째면 → rules-learned.md 로 승격
      ↓
다음 사이클 구축 전에 rules-learned.md 를 읽는다  ← 루프가 닫힌다
```

**승격 단계가 이 폴더의 핵심이다.** 이슈 로그만 있으면 문제는 쌓이기만 하고
같은 실수가 계속 반복된다. 규칙으로 올라가야 다음 사이클에서 걸린다.

## 원칙

1. **기록 없이 고치지 않는다.** "사소해서" 넘긴 것이 나중에 패턴으로 드러난다.
2. **재검수 없이 닫지 않는다.** 수정했다 ≠ 고쳐졌다. 검증된 이슈는 `quality/archive/<유형>/`에 보존하고 열린 이슈 목록에서는 제거한다.
3. **"동작합니다"는 검수가 아니다.** 사람이 눌러서 통과시킨 것만 검수다.
4. **치명·높음 이슈가 열려 있으면 배포하지 않는다.**
5. 규칙이 10개를 넘으면 해당 단계 가이드 본문으로 이관한다.
6. 새 오류 기록의 원인·조치·검수 근거를 Error Learning Agent가 종합해 `learning-log.md`와 필요한 규칙·검수 문서에 인제스트한다. 절차는 `guides/error-learning-ingest.md`를 따른다.

## 심각도 기준

| 등급 | 기준 | 배포 차단 |
|---|---|---|
| **치명** | 데이터가 손상되거나, 잘못된 사람에게 노출되거나, 핵심 경로가 막힘 | 차단 |
| **높음** | 주요 기능이 안 되거나, 우회 방법이 없음 | 차단 |
| **보통** | 불편하지만 우회 가능 | 다음 사이클로 미룰 수 있음 |
| **낮음** | 표기·정렬 등 사소한 것 | 백로그 |

# 재발 방지 규칙

> 같은 유형의 문제가 **2번째** 발생하면 여기에 규칙으로 올린다.
>
> - `issues.md` = 개별 사건의 기록 (과거)
> - 이 파일 = 앞으로의 행동 규칙 (미래)
>
> **구축을 시작하기 전에 이 파일을 읽는다.** 읽지 않으면 이 파일은 존재하지 않는 것과 같다.

### 작성 규칙

- **행동 지시문으로 쓴다.** "~에 주의한다"가 아니라 "~를 하기 전에 ~를 확인한다".
- 어느 단계에서 걸러야 하는지 명시한다 (S2 설계에서 막을 것인지, S6 구축에서 막을 것인지).
- 근거 이슈 번호를 반드시 남긴다. 나중에 이 규칙이 아직 유효한지 판단할 근거가 된다.

## 이관

규칙이 **10개를 넘으면** 옮긴다 — 이 파일이 길어지면 아무도 안 읽게 되고, 그러면 장치가 죽는다.

- 이 프로젝트에만 해당하는 규칙 → `CLAUDE.md` 6절(프로젝트 고유 규칙) 또는 `docs/spec/code-conventions.md`
- 모든 프로젝트에 통할 규칙 → 방법론 저장소(my_dev_method)에 수정 제안

**`docs/guides/`로는 이관하지 않는다.** guides는 새 프로젝트에 그대로 복사되는 불변 절차서라서,
여기에 이관하면 이 프로젝트의 사고 대응 규칙이 다음 프로젝트로 실려 간다.

# 검수 시나리오

> 사람이 **직접 눌러서** 확인할 목록. "동작합니다"라는 보고는 검수가 아니다.
> 사이클 구현이 끝나면 이 목록을 먼저 만들고, 그다음 사람이 순서대로 실행한다.
> **시나리오 작성은 프로파일과 무관하게** 아래 "반드시 포함할 것" 중 해당 유형 전부다.
> 프로파일이 정하는 것은 **수동 실행 횟수**다: Full 15~20회 · Standard 5~10회 · Lite 핵심 경로 1회 (`docs/guides/profiles.md`).
>
> **버그를 하나라도 잡아낸 시나리오는 자동 테스트로 승격한다.** 사람은 자동화되지 않은 항목부터 본다.
> 승격하지 않으면 이 목록은 사이클이 늘수록 아무도 돌리지 않는 목록이 된다.
> **성장 규칙**: `✅ 자동화됨` 시나리오는 사이클 종료 시 상세 절을 지우고 표의 한 줄(테스트 이름)만 남긴다 (`/cycle-close` 5단계).

**대상 사이클**: C00 — <이름>
**작성일**: YYYY-MM-DD
**최근 실행**: YYYY-MM-DD · 통과 0 / 실패 0 / 미실행 0

(작업 상태 어휘 `⬜ 대기` 등과 섞지 않는다 — 여기는 검수 결과 어휘다)

**`불가`는 진짜 불가일 때만 쓴다** — 시각적 인상, 실제 메일 수신, 외부 결제 승인 같은 것.
"귀찮아서"는 자동화 불가가 아니다.

## 반드시 포함할 것 ★ (목록의 정본)

정상 경로만 넣으면 검수가 아니다. 아래 중 **이 사이클에 해당하는 유형을 각각** 시나리오로 만든다
(화면이 없으면 새로고침·뒤로가기 등은 해당 없음으로 표기). `S6-build.md` 5-1의 프롬프트가 이 표를 가리킨다.

| 구분 | 확인할 것 |
|---|---|
| 필수값 누락 | 필수 항목을 비우고 진행하면 막히는가? 무엇이 문제인지 알려주는가? |
| 중복 실행 | 같은 동작을 두 번(빠르게 연달아 포함) 하면 두 건이 생기는가? |
| 권한 없음 | 권한 없는 계정으로 접근하면? 주소를 직접 치면? |
| 남의 데이터 | 다른 사용자의 것에 접근되는가? |
| 빈 상태 | 데이터가 하나도 없을 때 화면이 정상인가? |
| 대량 | 결과가 아주 많을 때 느려지거나 깨지지 않는가? |
| 중간 취소 | 진행 중 취소하면 어중간한 상태가 남는가? |
| 잘못된 입력 | 형식에 안 맞는 값, 아주 긴 값, 특수문자 |
| 상태 전이 | `docs/spec/domain.md`의 전이 표대로 움직이는가? 막아야 할 전이가 막히는가? |
| 새로고침 | 진행 중 새로고침하면 상태가 유지되는가? |
| 뒤로가기 | 브라우저 뒤로가기로 이상한 상태가 되는가? |
| 알림 | 알림이 실제로 오는가? 클릭하면 맞는 곳으로 가는가? |
| 자동 실행 | 배치·스케줄 작업이 실제로 도는가? 실패하면 알려지는가? |

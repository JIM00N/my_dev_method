## 5. 비즈니스 규칙 ★

**"항상 이러해야 한다"는 도메인 약속.** 상태 전이도 권한도 아닌데 구현이 반드시 지켜야 하는 것들이다.

| # | 규칙 | 왜 (근거) | 어기면 무슨 일이 | 어디서 강제하나 |
|---|---|---|---|---|
| 1 | | | | 도메인 경계 / 서버 / DB 제약 |

**여기 적을 것 / 적지 않을 것**

| 적는다 | 다른 절로 보낸다 |
|---|---|
| 어떤 조건이 무엇을 제한하는가 (동의 거부는 *가져오기*가 아니라 *전사 처리*를 막는다) | 상태가 무엇으로 바뀌나 → 3절 전이 표 |
| 무엇을 절대 하지 않는가 (원본 파일을 수정·삭제하지 않는다) | 누가 할 수 있나 → 4절 권한 |
| 계산·판정의 기준 (연락 우선순위는 마지막 접점 + 미해결 약속으로 정한다) | 화면에 어떻게 보이나 → `docs/spec/interface.md` |
| 한도·상한 (한 번에 가져올 수 있는 파일 20개) | 데이터의 형태 → 2절 데이터 목록 |

> **이 절이 왜 따로 있나 ★**
> 규칙은 전이표에도 권한표에도 안 들어가는데, 없으면 구현 중에 정확히 **지어내지는** 종류다.
> *"권한을 거부하면 파일 자체를 못 가져오나, 가져오되 전사만 못 하나?"* — 둘 다 말이 되고,
> 답이 없으면 에이전트가 하나 고른다. 다음 세션에서 다르게 고른다.
>
> **"어기면 무슨 일이" 칸을 비우지 않는다.** 못 적으면 그건 규칙이 아니라 취향이다 — 지운다.
